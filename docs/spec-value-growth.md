# Спецификация: value_growth — прирост стоимости пая

- **Статус:** утверждена 15.09.2026 (превью: https://claude.ai/artifact/PLVS28mZZgBeU97osdQ1fA)
- **Код:** `general_projects/fund_growth.py`, правка `general_projects/funds_perform/nav_perform.py`
- **Среда:** Python 3.13, pandas 3.0.5, numpy 2.5 — без новых зависимостей
- **capturedAtCommit:** null (каталог не git-репозиторий)

## Обзор

Функция принимает `pd.Series` со стоимостью пая фонда и возвращает `pd.Series` с приростом стоимости
относительно `start_date` на каждую дату до `finish_date`. Индекс ряда — даты или числа (1, 2, 3…).
При числовом индексе даты не участвуют, прирост считается от первого значения.

## Цели и не-цели

**Цели**
- Прирост от нуля на каждую дату периода, в том числе когда границы периода приходятся на выходные.
- Однозначный разбор `dd.mm.yyyy` (без угадывания месяц/день).
- Понятные ошибки на данных, где прирост не определён.

**Не-цели**
- Ограничение давности значения на границах (`max_lag_days` из `nav_growth`) — см. «Принятые риски».
- Перевод `nav_perform.py` (`nav_growth`, `growth_path`) на новую функцию — у них другая семантика.
- Приём строковых дат в индексе и строковых значений (например, «Не раскрывается»).

## Контракт

```python
def value_growth(
    series: pd.Series,
    start_date: str | pd.Timestamp | datetime | date | None = None,
    finish_date: str | pd.Timestamp | datetime | date | None = None,
    *,
    strict: bool = False,
    pct: bool = False,
) -> pd.Series:
```

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `series` | — | Стоимость пая: только float/int. Индекс — даты или числа |
| `start_date` | `None` | Строка `dd.mm.yyyy`, Timestamp, datetime или date; `None` — первая дата ряда |
| `finish_date` | `None` | То же; `None` — последняя дата ряда |
| `strict` | `False` | `True` — обе даты обязаны быть в ряду |
| `pct` | `False` | `True` — проценты (5.0) вместо доли (0.05) |
| результат | — | Series float64, `v / v0 - 1` (×100 при `pct`); имя ряда и имя индекса как у входа |

## Поведение

### Значения
1. Допустимы Python- и numpy-числа int/float. Строка, bool, Decimal и прочее —
   `ValueError("одно из значений не float/int: <индекс> → <значение> (<тип>)")`.
2. NaN и None означают «в этот день данных нет»: строки удаляются до расчёта.
3. Ряд пуст после удаления — `ValueError`.

### Числовой индекс (int/float dtype)
- Порядок строк как на входе, база — первое значение после удаления NaN.
- `start_date`, `finish_date`, `strict` игнорируются без предупреждения.
- Выход: тот же индекс (без строк с NaN).

### Индекс из дат (datetime64 dtype, в том числе tz-aware; или object-индекс из datetime/date)
1. Часовой пояс снимается (время на часах сохраняется), индекс обрезается до дня.
2. Индекс сортируется по исходной метке времени; за один день берётся последнее значение по времени.
3. `start_date`/`finish_date` приводятся к дню; `None` — первая/последняя дата ряда.
4. `start_date > finish_date` — ошибка. `start_date == finish_date` — одна строка 0.0.
5. `start_date` раньше первой даты ряда — ошибка (при любом `strict`).
6. `strict=True`: `start_date` и `finish_date` обязаны быть в индексе, иначе ошибка.
7. База — последнее значение на `start_date` или раньше. База ≤ 0 — ошибка.
8. Индекс выхода: `start_date`, все даты ряда строго между границами, `finish_date`.
   Отсутствующие границы добавляются. Значение на каждой дате — последнее на эту дату или раньше
   (для `finish_date` позже данных — последнее значение ряда).
9. Первая строка выхода всегда 0.0.

### Индекс другого типа
Строки, смешанные типы — `ValueError("индекс должен быть датами или числами …")`.

### Разбор дат
- Строки — только `dd.mm.yyyy` через `datetime.strptime`; пробелы по краям обрезаются.
  Причина: `pd.Timestamp("01.02.2026")` на pandas 3.0.5 даёт 2 января.
- Timestamp / datetime / date / np.datetime64 → `pd.Timestamp`, пояс снимается, время обрезается.
- Прочие типы — `TypeError`.

## Пример

Пай: 13.03 (пт) 100.0, 16.03 101.0, 17.03 102.0, 18.03 99.0, 19.03 103.0, 20.03 104.0.

```python
value_growth(pai, "14.03.2026", "22.03.2026")
# 14.03  0.00   ← база 100.0 с 13.03
# 16.03  0.01
# 17.03  0.02
# 18.03 -0.01
# 19.03  0.03
# 20.03  0.04
# 22.03  0.04   ← значение 20.03

value_growth(pai, "14.03.2026", "22.03.2026", strict=True)
# ValueError: strict=True: 14.03.2026 нет в ряду
```

## Ошибки

| Условие | Исключение и сообщение |
|---|---|
| Значение не float/int | `ValueError`: одно из значений не float/int: 17.03.2026 → 'н/д' (str) |
| После удаления NaN ряд пуст | `ValueError`: ряд пуст после удаления NaN |
| Индекс не даты и не числа | `ValueError`: индекс должен быть датами или числами |
| Строка даты не `dd.mm.yyyy` | `ValueError`: start_date: ожидается dd.mm.yyyy, получено '2026-03-14' |
| Дата неподдерживаемого типа | `TypeError`: start_date: ожидается строка dd.mm.yyyy или дата |
| `start_date` позже `finish_date` | `ValueError`: start_date 22.03.2026 позже finish_date 14.03.2026 |
| `start_date` раньше первой даты | `ValueError`: нет данных на 01.01.2025 или раньше: ряд начинается 01.06.2025 |
| `strict=True`, даты нет в ряду | `ValueError`: strict=True: 14.03.2026 нет в ряду |
| База ≤ 0 | `ValueError`: база на 13.03.2026 равна 0.0: прирост не определён |

Не ошибка: `finish_date` позже данных; границы на выходных при `strict=False`; NaN в ряду.

## Принятые риски

- Давность значения на `finish_date` не ограничена: фонд, переставший отчитываться в марте,
  покажет мартовский прирост на сентябрь. Вернуться к `max_lag_days`, если функция пойдёт
  в массовое сравнение фондов.

## Проверка

`python fund_growth.py` прогоняет самопроверку и печатает `OK`:

1. Суббота → воскресенье: выход ровно как в примере
2. Тот же вызов со `strict=True` — ValueError
3. «01.02.2026» — 1 февраля
4. `finish_date` с 14:35:12.123 включает пай 18:00 того же дня
5. Два значения за день — последнее по времени
6. Числовой индекс — база первое значение, даты игнорируются
7. NaN удаляется, база с последнего непустого
8. Строка в значениях — «одно из значений не float/int»
9. bool в значениях — ValueError
10. `start_date` раньше первой даты — ValueError
11. `finish_date` позже последней даты — последнее значение
12. `pct=True` — значения ×100
13. `start_date` позже `finish_date` — ValueError
14. База ≤ 0 — ValueError
15. Индекс-строки — ValueError
16. `None` / `None` — весь ряд, первая строка 0.0
17. `start_date == finish_date` — одна строка 0.0

Плюс регрессия: `nav_growth("01.02.2026", …)` считает от 1 февраля.

## Dependency Graph & Implementation Order

```
_parse_date ──┐
              ├──> value_growth ──> самопроверка ──┐
_check_values ┘                                    ├──> прогон
nav_growth: разбор дат (nav_perform.py) ───────────┘
```

1. `_parse_date` — строка dd.mm.yyyy, Timestamp, datetime → день без времени и пояса; None пропускается.
2. `_check_values` — float/int без bool; NaN и None — пропуск; иначе «одно из значений не float/int».
3. `value_growth` — развилка по индексу, strict, окно с границами, v / v0 − 1, pct.
4. Самопроверка — 17 проверок под `__main__`.
5. Исправление `nav_growth` — явный разбор dd.mm.yyyy в nav_perform.py; не зависит от шагов 1–4.
6. Прогон — `python fund_growth.py` → OK; `nav_growth` на «01.02.2026» даёт 1 февраля.
