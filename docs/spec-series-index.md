# Спецификация: `series_index` — доходность взвешенного композита по переданным рядам (уровни или ставки)

Модуль: `general_projects/moex_cls.py`. Интервью и реализация: 16.09.2026. Статус: реализовано, проверено.
Родственная функция: `custom_index` (`spec-custom-index.md`) — та же методика, но котировки тянутся с MOEX.

## Обзор

То же, что `custom_index`, только вместо тикеров передаются готовые `pd.Series` (индекс — даты, значения — float):
ряды из Cbonds/Bloomberg, СЧА или пай фонда, уже выгруженные свечи. Функция — **независимая копия**:
`custom_index` её не вызывает, правки методики нужно вносить в обе.

## Интерфейс

```python
series_index(pairs, start_date=None, finish_date=None, name=None, *, cumulative=False) -> pd.Series

series_index([(rucb, 0.5), (imoex, 0.5)], "01.01.2026", "15.09.2026", "50/50")
series_index(zip([rucb, imoex], [0.5, 0.5]), name="50/50")       # весь общий период
series_index([(ruonia, 1)], "01.01.2026", "15.09.2026", "overnight", cumulative=True)  # ставка -> доход
```

| Аргумент | Смысл |
|---|---|
| `pairs` | список (любой итерируемый, кроме dict/Series/DataFrame/str) пар `(pd.Series, вес)`. Вес — конечное число > 0 (bool нельзя), сумма = 1 ± 1e-9 |
| `start_date`, `finish_date` | `'DD.MM.YYYY'`, `'YYYY-MM-DD'`, date/datetime (через `parse_date`), включительно; `None` — начало/конец общего периода |
| `name` | имя возвращаемой Series, по умолчанию `None` |
| `cumulative` | `False` — ряды это уровни (индекс, пай, цена); `True` — ряды это ставки overnight в **% годовых** (21.35), результат — доход от вложения под них. Флаг общий: смешать в одном вызове уровень и ставку нельзя |

Запись `{series: weight}` невозможна: `pd.Series` не хешируется, словарь падает с `TypeError` ещё до вызова функции.
Если передан dict, ошибка объясняет это.

Возврат — как у `custom_index`: float64, `DatetimeIndex` с именем `date` (общие даты рядов в окне),
накопленная доходность в долях, первая строка `0.0`.

## Алгоритм

1. Проверка пар и весов — до любой работы с рядами.
2. Каждый ряд приводится как в `value_growth`: время и часовой пояс отбрасываются (`tz_localize(None)`), сортировка,
   NaN/None/pd.NA удаляются, из нескольких значений за день берётся последнее по времени.
3. Обрезка окном `[start_date, finish_date]` (`None` — без обрезки с этой стороны).
4. Inner join уровней по датам; доходности рядов между соседними общими датами — **после** join.
5. `R = Σ wᵢ·rᵢ` на каждом шаге, `G = Π(1+R) − 1`, `G = 0` на первой общей дате.
   Шаг `rᵢ` между соседними общими датами `t_prev → t`:
   - `cumulative=False`: `P_t / P_prev − 1`;
   - `cumulative=True`: `ставка_prev / 100 · (t − t_prev).days / 365`.

### Режим ставок (`cumulative=True`)

- Ставка даты действует **все календарные дни до следующей даты ряда**: в выходные, праздники и пропуски — последняя
  известная ставка. За пропуск начисляется простой процент одним шагом (пятница: `1 + r·3/365`), без капитализации по дням —
  как у сделки overnight с пятницы на понедельник.
- База дней — 365 всегда, в том числе в високосный год.
- Ставка последней даты в окне не начисляется: неизвестно, до какого дня она действует. Выход заканчивается на последней
  общей дате, начисление после неё до `finish_date` не делается.
- Композит ставок равен одному ряду со ставкой `Σ wᵢ·ставкаᵢ`. Inner join как в режиме уровней: дата, которая есть только
  у одного ряда, выпадает, и за неё действует ставка композита на предыдущую общую дату.
- Нулевые и отрицательные ставки разрешены.

При разной частоте рядов (дневной индекс + недельный пай) шаги и ребалансировка идут по общим — недельным — датам.

## Ошибки и предупреждения

| Ситуация | Реакция |
|---|---|
| `pairs` — dict, Series, DataFrame, строка, не итерируемое; пустой список | `ValueError` |
| Элемент не пара из двух | `ValueError` «пара №N: … получено tuple длины 3» |
| Вес ≤ 0, NaN/inf, bool, не число; сумма ≠ 1 | `ValueError` |
| Не `pd.Series`; значения bool, строки, Decimal и прочие не-числа | `ValueError` с рядом и датой |
| Индекс не из дат (числа, строки) | `ValueError`; допустимы datetime64 и object из date/datetime |
| Ряд пуст после удаления NaN; значение ±inf; значение ≤ 0 (только при `cumulative=False`) | `ValueError` с рядом (и датой) |
| `start_date > finish_date`, непонятная дата | `ValueError` |
| У ряда нет данных в окне; у рядов нет общих дат | `ValueError` с рядом / диапазонами всех рядов |
| Первая общая дата позже заданного `start_date` > 10 дней, или последняя раньше `min(finish_date, сегодня МСК)` > 10 дней | `UserWarning` с виновными рядами; для `None`-границы проверки нет |

Ряд в сообщениях называется по `Series.name`, без имени — «ряд №N» (N — позиция в `pairs`, с 1).
Одинаковые имена не мешают расчёту: внутри ряды различаются по позиции.

## Проверка

Прогон 16.09.2026 (`scratchpad/check_series_index.py`), все пункты прошли:
- на живых рядах из `get_candles` результат совпадает с `custom_index` до 1e-15: 50% RUCBTRNS + 50% IMOEX, 20/20/60 RUABITR/MCFTR/MCFTRR,
  мёртвый RUCBITR + IMOEX за 2023–2026 (то же предупреждение «RUCBITR по 31.05.2023»);
- с `None`-границами — тот же ряд без предупреждений; `zip(ряды, веса)` работает;
- ручной расчёт на синтетике; «грязный» ряд (время, пояс, два значения за день, NaN, перемешан) даёт тот же результат, что чистый;
  индекс из `datetime.date`, разные unit индексов, `Float64` с `pd.NA`;
- одна общая дата → `[0.0]`; разная частота → шаги по общим датам;
- живые ряды по 15.09 и `finish_date` в будущем — без предупреждения; синтетика по 09.01 — с предупреждением;
- все ошибки из таблицы.

Режим ставок (`scratchpad/check_rates.py`), все пункты прошли:
- **живая сверка с биржей**: RUSFAR (ставка) → `cumulative=True` против `RUSFARIND` (биржевой индекс накопленной доходности)
  за 09.01.2025–15.09.2026: 33.2744% против 33.2717%, разница 0.27 б.п., максимум по датам 0.42 б.п.
  Капитализация по дням внутри пропусков даёт 1.41 б.п., сдвиг ставки на дату вперёд — 1.78 б.п.: выбранная конвенция ближе всего;
- 10% каждый календарный день 2025 года = `(1 + 0.1/365)^365 − 1`; по рабочим дням — простой процент за выходные, результат чуть меньше;
- ручной расчёт с разными ставками и пропусками; пятница → понедельник = `20% · 3/365`; ставка последней даты не используется;
- 30% R + 70% Q = один ряд `0.3R + 0.7Q`; дата только у одного ряда выпадает;
- ставки −0.5% и 0% работают; `inf` — ошибка; в режиме уровней отрицательное значение — по-прежнему ошибка;
- регрессия режима уровней (`check_series_index.py`, включая сверку с `custom_index`) — без изменений.
