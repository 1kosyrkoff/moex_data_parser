# Спецификация: `custom_index` — доходность кастомного взвешенного индекса

Модуль: `general_projects/moex_cls.py`. Интервью и реализация: 16.09.2026. Статус: реализовано, проверено на живом ISS.

## Обзор

Функция считает накопленную доходность композита из нескольких инструментов MOEX с фиксированными весами
(«50% RUCBTRNS + 50% IMOEX», «20% RUABITR + 20% MCFTR + 60% MCFTRR») за период. Котировки берутся
существующей `get_candles`, которая сама определяет engine/market/board через `find_board`
(IMOEX — SNDX, RUABITR/MCFTR/RUCBTRNS — RTSI, SBER — TQBR и т.д.).

## Интерфейс

```python
custom_index(weights: dict, start_date, finish_date, name: str, *, intraday: bool = False) -> pd.Series
```

| Аргумент | Смысл |
|---|---|
| `weights` | `{тикер: вес}`. Тикеры приводятся `strip().upper()`. Каждый вес — конечное число > 0 (bool нельзя), сумма = 1 с допуском 1e-9 |
| `start_date`, `finish_date` | `'DD.MM.YYYY'`, `'YYYY-MM-DD'` или date/datetime; разбираются `parse_date` (strptime), обе границы включительно |
| `name` | имя возвращаемой Series |
| `intraday` | `False` — свеча, датированная сегодняшним днём по Москве, отбрасывается; `True` — остаётся |

Возврат — `pd.Series` float64:
- индекс `DatetimeIndex` с именем `date` — даты в `[start_date, finish_date]`, где котировка есть у **всех** тикеров;
- значения — накопленная доходность композита в долях (0.0123 = 1.23%), первая строка ровно `0.0`,
  последняя — доходность за весь период;
- `Series.name = name`.

## Алгоритм

1. Проверка весов (см. «Ошибки»).
2. По каждому тикеру `get_candles(ticker, start, finish, "1d")` → колонка `close`, NaN удаляются.
   При `intraday=False` отбрасывается свеча с датой = сегодня (МСК, фиксированный UTC+3).
3. Inner join уровней `close` по датам.
4. Доходность тикера между соседними общими датами: `rᵢ,ₜ = Pᵢ,ₜ / Pᵢ,ₜ₋₁ − 1`.
5. Доходность композита за шаг — ежедневная ребалансировка: `Rₜ = Σ wᵢ · rᵢ,ₜ`.
6. Накопленная: `Gₜ = Π(1 + R) − 1`, на первой общей дате `G = 0`.

**Доходности считаются после join, а не до.** Облигационные индексы с 25.04.2026 считаются и в выходные,
акционные — нет. Если посчитать дневные доходности до join, доходность субботы и воскресенья выпадет вместе
с этими датами, а понедельник понесёт только движение воскресенье→понедельник. После join понедельник несёт
всё движение с пятницы.

## Ошибки и предупреждения

| Ситуация | Реакция |
|---|---|
| `weights` не словарь или пустой | `ValueError` |
| Дубль тикера после `strip().upper()` (`imoex` и `IMOEX`) | `ValueError` |
| Вес ≤ 0, NaN/inf, bool, не число | `ValueError` с тикером |
| `|Σw − 1| > 1e-9` (в т.ч. проценты `{50, 50}`) | `ValueError` с фактической суммой |
| `start_date > finish_date`, непонятная дата | `ValueError` из `get_candles` / `parse_date` |
| Тикера нет на MOEX | `ValueError` из `find_board` |
| У тикера нет ни одной свечи за период | `ValueError` с тикером; если отброшена сегодняшняя свеча — подсказка про `intraday` |
| Котировка ≤ 0 | `ValueError` с тикером и датой |
| У тикеров нет общих дат | `ValueError` с диапазонами каждого тикера |
| Первая общая дата позже `start_date` больше чем на 10 дней, или последняя раньше `min(finish_date, сегодня)` больше чем на 10 дней | `UserWarning` с виновными тикерами и фактическим периодом; ряд возвращается |
| Сетевые ошибки ISS | пробрасываются как есть (`requests`) |

Порог 10 календарных дней выбран так, чтобы разные календари SNDX/RTSI, выходные облигационных индексов
и новогодние праздники не давали ложных предупреждений.

## Граничные случаи

- `start_date` — выходной/праздник: первая строка (0.0) на первой общей дате после него; движение до неё в ряд не входит.
- Дыра у одного тикера внутри периода не предупреждается: доходность через дыру считается одним шагом по общим датам.
- Одна общая дата — Series из одного `0.0`.
- Один тикер с весом 1 — ровно `close / close₀ − 1`.
- Не-индексы (акции, валюта, облигации) разрешены без проверок; их `close` — цена без дивидендов и купонов.
- `RUCBITR` не считается с **31.05.2023** (`is_traded=0`), актуальный индекс корпоративных облигаций совокупного дохода — `RUCBTRNS` (с 29.12.2018).
- `MCFTRNS` на MOEX нет: `MCFTR` — брутто, `MCFTRR` — нетто по ставкам российских организаций, `MCFTRN` — нетто по ставкам иностранных.
- У закрытых дневных свечей 2026 года `end` бывает 23:59:55–23:59:58 (раньше всегда 23:59:59), поэтому незакрытая свеча определяется по дате, а не по `end`.
- `MCFTRR`/`MCFTRN` публикуют значение за день только после закрытия; внутри дня у `IMOEX`/`RUCBTRNS` уже есть свеча за сегодня.

## Проверка

Прогон на живом ISS 16.09.2026, все пункты прошли:
- 50% RUCBTRNS + 50% IMOEX за 01.01–15.09.2026 совпадает с ручным пересчётом до 1e-14; выходных дат в ряду нет;
  понедельник 27.04.2026 несёт доходность с пятницы 24.04.2026.
- 20% RUABITR + 20% MCFTR + 60% MCFTRR (тикеры в разном регистре и с пробелами) — без предупреждений.
- `{IMOEX: 1}` = `close/close₀ − 1`; `'01.02.2026'` разобрано как 1 февраля.
- RUCBITR + IMOEX за 2023–2026 — warning «RUCBITR по 31.05.2023», ряд до 31.05.2023; за 2025–2026 — `ValueError`.
- RUCBTRNS + IMOEX с 2017 — warning «RUCBTRNS с 29.12.2018».
- Старт 01.01 и `finish_date` в будущем — без ложных предупреждений.
- Все ошибки весов, дубли, пустой словарь, перепутанные даты, `MCFTRNS`.
- `intraday=False` заканчивается вчера, `intraday=True` — сегодня.

## Dependency Graph & Implementation Order

```
parse_date ──┐
find_board ──┴──▶ get_candles ──▶ custom_index
```

1. Валидация весов (не зависит от сети).
2. Разбор дат через `parse_date`, загрузка `get_candles` по каждому тикеру, фильтр `intraday`, проверка пустых/неположительных.
3. Inner join уровней, проверка пустого пересечения, предупреждение о сужении периода.
4. Доходности, `Σ w·r`, цепочка, оформление Series.
5. Проверка на живом ISS (список выше).
