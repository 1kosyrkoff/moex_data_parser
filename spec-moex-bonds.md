# `moex_bonds.py` — описание, инструкции, логика функций

Рабочий справочник к модулю [`moex_bonds.py`](moex_bonds.py): что вызывать, что приходит
в ответ, как устроен каждый шаг расчёта.

Обоснование конвенций (почему T+1, почему `CLOSE`, почему НКД считаем сами, цифры сверок
с биржей, decisions log) — в [`docs/spec-moex-bond-yields.md`](docs/spec-moex-bond-yields.md).
Здесь только механика: **что делает** и **как делает**, без повторного пересказа «почему».

---

## Что это

Клиент к MOEX ISS по облигациям. Четыре публичные функции, одна общая схема:
ISIN → SECID → данные биржи → DataFrame.

| функция | вход | отдаёт |
|---|---|---|
| `get_bond_yields` | список ISIN + дата оценки | YTM и YTP на дату, ACT/365 |
| `get_coupon_schedule` | список ISIN | полное расписание выплат, одна строка = одна дата |
| `get_bond_card` | **один** ISIN | досье на выпуск: 6 таблиц (паспорт, котировки, расписание, режимы, индексы, обороты) |
| `get_issuer_sector` | список ISIN | сектор экономики эмитента + ИНН |

Общие свойства всех четырёх:

- **Ключи и авторизация не нужны** — ISS отдаёт данные публично.
- **Одна битая бумага не роняет пачку.** Исключения ловятся внутри цикла по ISIN, причина
  пишется в колонку `STATUS`. Единственное исключение — `get_bond_card`: она про одну бумагу
  и бросает `ValueError` / `TypeError` наружу.
- **Кеш на процесс.** Справочник рынка, расписания по SECID, метаданные колонок и карта
  секторов складываются в `_CACHE` и живут до перезапуска питона.

## Зависимости и импорт

`requests`, `pandas`, работающий интернет. Таймаут запроса 60 с, свой User-Agent,
HTTP-ошибки поднимаются через `raise_for_status()`.

```python
import sys
sys.path.append('/Users/skosyrkov/pyprojects/general_projects/claude_repo/claude_codes/useful_functions')

from moex_bonds import (get_bond_yields, get_coupon_schedule,
                        get_bond_card, get_issuer_sector)
```

Прогон демо-примеров: `python moex_bonds.py` — блок `__main__` считает доходности,
расписание, карточку и секторы по трём тестовым ISIN.

## 1. `get_bond_yields` — YTM и YTP

```python
get_bond_yields(isins, date=None, price="close", lookback=20,
                assumed_rate=None, details=False) -> pd.DataFrame
```

### Параметры

| параметр | что принимает | по умолчанию | смысл |
|---|---|---|---|
| `isins` | список ISIN или один ISIN строкой | — | регистр и пробелы нормализуются сами |
| `date` | `date`, `datetime`, `'YYYY-MM-DD'`, `'DD.MM.YYYY'`, `'DD/MM/YYYY'`, `'YYYYMMDD'`, `'DD.MM.YY'` | сегодня | дата оценки |
| `price` | `'close'`, `'legal'`, `'mp3'`, `'wap'`, число, словарь `{ISIN: цена}` | `'close'` | источник цены; число и значения словаря — % от номинала |
| `lookback` | int, дней | 20 | на сколько откатываться назад, если в дату оценки сделок не было |
| `assumed_rate` | % годовых | `None` | ставка для необъявленных купонов; `None` → последняя известная ставка выпуска |
| `details` | bool | `False` | `True` добавляет 14 колонок диагностики |

Строковые значения `price` — это цепочки полей истории, берётся первое непустое:

| значение | цепочка полей ISS |
|---|---|
| `'close'` | `CLOSE` |
| `'legal'` | `LEGALCLOSEPRICE` → `CLOSE` |
| `'mp3'` | `MARKETPRICE3` → `LEGALCLOSEPRICE` → `CLOSE` |
| `'wap'` | `WAPRICE` → `CLOSE` |

`date` разбирается своим `parse_date`, а не `pd.Timestamp`: `'01.02.2026'` здесь
**1 февраля**, тогда как `pd.Timestamp` прочитал бы это как 2 января.

### Результат

При `details=False` — четыре колонки:

| колонка | что внутри |
|---|---|
| `ISIN` | как передали, в верхнем регистре |
| `YTM` | эффективная доходность к погашению, % годовых, ACT/365, округление до 4 знаков |
| `YTP` | то же к ближайшей **put**-оферте; `NaN`, если оферты нет |
| `COUPONS` | `known all coupons` — все купоны до погашения объявлены биржей; `unknown coupons` — часть посчитана по перенесённой ставке |

При `details=True` добавляются: `SECID`, `SHORTNAME`, `DATE` (дата оценки), `SETTLE`
(дата расчётов T+1), `PRICE` (чистая цена, % от номинала), `PRICE_DATE` (**фактическая**
дата этой цены), `PRICE_FIELD` (какое поле сработало), `ACCRUED` (НКД в валюте выпуска
на `SETTLE`), `FACEVALUE` (непогашенный номинал на `SETTLE`), `FACEUNIT`, `MATDATE`,
`PUTDATE`, `EST_COUPONS` (сколько купонов посчитано по перенесённой ставке), `STATUS`.

```python
get_bond_yields(['RU000A0ZZ5H3', 'RU000A1032P1'], date='2026-09-04', details=True)
```

### `STATUS`: когда доходности нет

| `STATUS` | что произошло | что делать |
|---|---|---|
| `ok` | расчёт прошёл | — |
| `не найден на MOEX` | ISIN нет ни в справочнике торгуемых, ни в общей базе | проверить ISIN; внебиржевые выпуски биржа не знает |
| `выпуск погашен на дату оценки` | `MATDATE` ≤ дата оценки | взять дату раньше погашения |
| `нет купонного расписания в ISS` | `bondization` пуст и по купонам, и по амортизациям | данных нет, считать нечем |
| `нет цены за N дней до даты оценки` | сделок не нашлось ни в окне `lookback`, ни в первых 90 днях торгов | увеличить `lookback`, сменить `price` на `'mp3'`/`'legal'` или задать цену вручную |
| `погашение до даты расчетов T+1` | выпуск гасится раньше, чем уходят расчёты | доходность не определена |
| `номинал полностью погашен на дату расчетов` | амортизация разошлась к `SETTLE` | бумага фактически мертва |
| `ставка купона неизвестна, N купонов не восстановлены` | у выпуска **ни одного** объявленного купона — переносить нечего | задать `assumed_rate` вручную |
| `бессрочная бумага: доходность к погашению не определена` | `MATDATE` пуст (`'0000-00-00'`) | смотреть `YTP`, если есть put |
| `ошибка запроса: …` | сеть или ISS | повторить |
| `ошибка расчета: …` | неожиданная форма данных по этой бумаге | смотреть текст; остальные бумаги пачки посчитаны |

`YTM` может прийти `NaN` и при `STATUS='ok'` — когда бисекция не нашла корня (цена вне
диапазона потоков) или ближайший поток попал на саму дату расчётов. `YTP` считается
независимо от `YTM`: у бумаги без восстановимой ставки до погашения `YTP` к близкой
оферте всё равно может посчитаться.

## 2. `get_coupon_schedule` — расписание выплат

```python
get_coupon_schedule(isins) -> pd.DataFrame
```

Всё, что ISS знает по выпуску, включая прошедшие выплаты. **Дата в пределах выпуска
встречается ровно один раз:** купон, транш амортизации и оферта одного дня лежат в одной
строке, каждый в своей колонке. Сортировка по `ISIN`, `date`; даты приведены
к `datetime64`, суммы — к `float`.

19 колонок:

| группа | колонки |
|---|---|
| идентификация | `ISIN`, `SECID`, `SHORTNAME`, `FACEUNIT` |
| дата и купонный период | `date`, `STARTDATE`, `RECORDDATE` |
| суммы дня (наш расчёт) | `coupon_amount`, `rate`, `amort_amount`, `total_amount`, `FACEVALUE` |
| оферта | `OFFERPRICE`, `offer_amount`, `OFFERSTART`, `OFFEREND`, `CALLOPTIONDATE`, `PUTOPTIONDATE` |
| служебное | `STATUS` |

Соглашение по регистру: **наш расчёт — snake_case, сырые поля ISS — ВЕРХНИЙ регистр.**

Тип события отдельной колонкой не дублируется, он читается из самих колонок:

| событие на дату | признак |
|---|---|
| купон | заполнен `STARTDATE` (он есть и у ещё не объявленного купона) |
| погашение номинала | заполнен `amort_amount` |
| оферта | заполнены `OFFERPRICE` и/или `OFFERSTART`/`OFFEREND` |
| погашение выпуска | последняя дата расписания (ставится всегда, даже если номинал разошёлся амортизацией раньше — тогда там `amort_amount = 0`) |

Что важно помнить при чтении:

- `coupon_amount` и `rate` — **сырые**: необъявленный купон это `NaN`, а не оценка.
  Расписание показывает факт, доходности в `get_bond_yields` считаются с переносом ставки —
  расхождение намеренное.
- `total_amount` = `coupon_amount` + `amort_amount`, но **пустой, если купон дня
  не объявлен**, даже при известном транше: сумма выплаты дня неизвестна, слагаемые видны
  в своих колонках.
- `offer_amount` (цена оферты × непогашенный номинал) в `total_amount` **не входит** —
  оферту ещё надо предъявить.
- `FACEVALUE` — непогашенный номинал, действующий на дату события, посчитанный из расписания
  амортизаций; транш этой же даты в нём ещё не погашен. Одноимённое поле ISS для этого
  не годится: оно отдаёт текущий номинал во всех строках подряд.
- `CALLOPTIONDATE` / `PUTOPTIONDATE` проставлены только в строке, чья дата с ними совпала:
  в ISS это скаляры уровня выпуска, а не свойство периода. Тип остальных оферт расписания
  восстановить нечем — `offertype` не отличает put от call.

Ненайденный или сломавшийся выпуск даёт одну строку с пустой `date` и причиной в `STATUS`.
Живые строки: `df[df.STATUS.isna()]`.

## 3. `get_bond_card` — досье на выпуск

```python
card = get_bond_card('RU000A0ZZ5H3')   # строго один ISIN строкой
```

Словарь из шести DataFrame:

| ключ | что внутри | форма |
|---|---|---|
| `passport` | паспорт выпуска: эмитент, регномер, даты, номинал, купон, листинг, флаги дефолта | `Показатель / Значение / Поле` |
| `quotes` | котировки и параметры торгов основного режима — три блока ISS в одной длинной таблице | `Показатель / Значение / Поле / Блок` |
| `schedule` | расписание выплат, ровно как у `get_coupon_schedule` | 19 колонок |
| `boards` | все режимы торгов с диапазонами истории | русские подписи |
| `indices` | индексы MOEX, куда бумага входила, с датами включения | русские подписи |
| `aggregates` | обороты по рынкам за последний торговый день | русские подписи |

- Подписи и типы берутся из метаданных самой биржи (`iss_columns`, `description.title`),
  поэтому новые поля ISS появляются в карточке без правок кода.
- Список вместо строки → `TypeError`, ненайденный ISIN → `ValueError`. Для пачки — цикл.
- Истории торгов в карточке нет сознательно: это паспорт, а не котировочная лента. Дневные
  свечи — `moex_cls.get_candles`.
- Доходности в `quotes` — **биржевые** (`YIELD`, `YIELDTOOFFER`, `EFFECTIVEYIELD`,
  `DURATION`). Наши, с переносом ставки и дисконтированием от T+1, живут только
  в `get_bond_yields`.
- Пустых ячеек в `quotes` много: биржа отдаёт все поля рынка, включая неприменимые.
  Фильтр: `card['quotes'].dropna(subset=['Значение'])`.

## 4. `get_issuer_sector` — сектор эмитента

```python
get_issuer_sector(isins) -> pd.DataFrame
```

Колонки: `ISIN`, `SECTOR`, `SOURCE`, `EMITENT`, `INN`, `SECID`, `TICKER`, `BONDTYPE`, `STATUS`.

Своего справочника секторов MOEX не публикует (`SECTORID` пуст у всех бумаг), поэтому сектор
выводится двумя путями, и `SOURCE` всегда говорит, каким:

| `SOURCE` | как определён | покрытие |
|---|---|---|
| `отраслевой индекс MOEX` | эмитент сам торгуется акциями, входящими в один из десяти отраслевых индексов (`MOEXOG`, `MOEXEU`, `MOEXTL`, `MOEXMM`, `MOEXFN`, `MOEXCN`, `MOEXCH`, `MOEXTN`, `MOEXIT`, `MOEXRE`) | ~990 из 4041 торгуемых облигаций, из них ~700 «Финансы» |
| `тип выпуска` | ОФЗ, бумаги ЦБ, субфедеральные, муниципальные, МФО — сектор задан типом | ~165 бумаг |

Потолок — около **29% торгуемых облигаций**. У остальных `SECTOR` пуст и
`STATUS = 'эмитент не представлен в отраслевых индексах MOEX'`: облигации обычно выпускают
дочерние SPV со своим ИНН, у которых акций нет, а связи «дочка — материнская компания»
в ISS нет вообще. Для таких выпусков в `INN` лежит ИНН эмитента — сектор добирается
из внешнего источника с ОКВЭД (ЕГРЮЛ, dadata).

## Логика расчёта доходности: конвейер

Один проход по одному ISIN в `get_bond_yields`. Каждый шаг — отдельная функция, её можно
вызвать и отладить в одиночку.

**1. ISIN → выпуск.** `find_bond(isin)`
Сначала справочник торгуемых бумаг `market_snapshot()` (один запрос на всю сессию), затем,
если не нашлось, поиск по всей базе ISS плюс `description` — так находятся погашенные
и делистингованные. У ОФЗ `SECID ≠ ISIN`, поэтому искать можно только по базе.
Отдаёт словарь статики: `SECID`, `BOARDID`, `MATDATE`, `FACEVALUE`, `CALLOPTIONDATE`,
`PUTOPTIONDATE`, `BUYBACKDATE`, `BUYBACKPRICE`, тип выпуска.

**2. Расписание.** `get_bondization(secid)` → `{'coupons', 'amortizations', 'offers'}`,
три DataFrame как есть от ISS, кеш по SECID.

**3. Цена.** `get_price(secid, date, price, lookback, board)`
Запрашивается окно истории от `date − lookback` до `date + 10` по **основной доске**
(без доски ISS смешал бы режимы: у валютных выпусков TQCB и TQOD с разными ценами).
Внутри окна идём от даты оценки назад и берём первое непустое поле из цепочки `price`.
Если не нашлось — `_first_traded_row`: первая рыночная цена выпуска за первые 90 дней торгов.
Возвращает `{'price', 'date', 'field', 'face', 'sessions'}`, где `face` — номинал, который
биржа показывает на эту дату, а `sessions` — биржевой календарь из окна (нужен для T+1).

**4. Дата расчётов.** `next_trading_day(date, sessions)`
Первая сессия из календаря после даты оценки; если будущих сессий в истории ещё нет
(оценка на сегодня) — ближайший будний день. **Вся дальнейшая математика идёт от `SETTLE`,
не от даты оценки.**

**5. Масштаб амортизаций.** `normalize_amortizations(amortizations, face_биржи, дата_цены)`
Сумма расписания сравнивается с биржевым `FACEVALUE`; расхождение больше 0.5% →
все суммы умножаются на коэффициент. Лечит удвоенные расписания замещающих ОФЗ и округление
у копеечных номиналов. Форме расписания доверяем, масштаб берём с рынка.

**6. Ставка для необъявленных купонов.** `last_known_rate(coupons, amortizations)`
Самый свежий объявленный купон, **включая будущие** (после оферты эмитент переставляет
ставку, и объявленный вперёд купон свежее последнего выплаченного). Если `valueprc` пуст —
а у флоатеров он пуст почти всегда — ставка восстанавливается из суммы:
`rate = value / (номинал × дней / 365) × 100`. Параметр `assumed_rate` перебивает этот шаг.

**7. Точность округления.** `value_decimals(coupons)`
Число знаков берётся из фактических сумм купонов выпуска, от 2 до 8: у замещающих ОФЗ купон
бывает 0.0015, и округление до копеек обнулило бы и купон, и НКД.

**8. Номинал и НКД на `SETTLE`.**
`face_at(amortizations, settle, fallback)` — сумма всех амортизаций **после** даты.
`fallback` подставляется только при пустом расписании, чтобы бессрочные не выглядели
погашенными; ноль по непустому расписанию законен.
`accrued_interest(...)` — ищем период `startdate ≤ settle < coupondate` и берём
пропорцию: `НКД = value × (settle − startdate) / (coupondate − startdate)`. Если `value`
не объявлен, он сначала считается из ставки: `value = номинал × rate/100 × дней/365`.
Считаем сами, а не берём `ACCINT`: биржевое поле привязано к дате торгов, а у валютных
выпусков выражено в рублях, тогда как цена и номинал — в валюте номинала.

**9. Грязная цена.** `dirty = clean × face / 100 + НКД` — в валюте номинала, на одну бумагу.

**10. Денежные потоки.** `bond_cashflows(bondization, settle, till, rate, redemption_price, …)`
`till` — дата выбытия (погашение для YTM, дата оферты для YTP). В поток попадают:
амортизации строго между `settle` и `till`, купоны с `settle < дата ≤ till`, и остаток
номинала на `till` по цене `redemption_price` (100% для погашения, цена оферты для put).
Купоны считаются от непогашенного номинала, поэтому амортизация уменьшает их сама собой.
Необъявленные купоны считаются по `rate` и считаются в `attrs['estimated']`; если переносить
нечего — в `attrs['lost']`, и доходность не считается. **НКД к выкупу по оферте
не добавляется** — так считает биржа.

**11. Доходность.** `effective_yield(flows, dirty, settle)`
`NPV(потоки) = грязная цена`, ACT/365, годовое сложение, бисекция на отрезке
от −99.9% до 100000% годовых, 300 итераций или `tol = 1e-12`, результат в % с 4 знаками.
`None`, если потоков нет, цена ≤ 0, ближайший поток попал на `settle` или корня
на отрезке нет.

**12. Оферта.** `put_date(info, offers, settle, maturity)`
Кандидаты: оферты расписания после `settle`, раньше погашения, не совпадающие
с `CALLOPTIONDATE` и без слова «погашение» в типе, плюс скаляры `BUYBACKDATE`
и `PUTOPTIONDATE`. Берётся ближайшая; если в пределах 5 дней стоит пара дат (сбор заявок
и расчёты) — поздняя из пары. Цена: цена оферты, иначе `BUYBACKPRICE`, иначе 100%.
Call-оферты в YTP не входят: это право эмитента, а не держателя.

## Справочник функций по слоям

### Транспорт и приведение типов

| функция | что делает |
|---|---|
| `_iss(path, **params)` | GET к ISS с `iss.meta=off` → json; таймаут 60 с, `raise_for_status` |
| `_block(payload, name)` | блок ответа `{'columns', 'data'}` → DataFrame |
| `_date(value)` | `'YYYY-MM-DD'` → `date`; пустое и `'0000-00-00'` (бессрочные) → `None` |
| `_num(value)` | значение ISS → `float`; пустое, `None`, `NaN`, нечисло → `None` |
| `_typed(value, kind)` | приводит строку ISS к типу, который указала сама биржа |
| `_total(*values)` | сумма непустых; **все пустые → `None`**, а не 0: выплаты в этот день нет |
| `parse_date(value, name)` | единственная публичная из слоя: шесть форматов даты → `date`, иначе `ValueError` |

## Кеш и стоимость запросов

`_CACHE` — один словарь на процесс: `market`, `bondization` (по SECID), `static`,
`columns`, `sectors`, `emitters`. Без TTL: данные живут до перезапуска питона.

| вызов | запросов |
|---|---|
| первая бумага в сессии | +1 справочник рынка |
| доходность на бумагу | 2 (расписание + окно истории) |
| расписание на бумагу | 1, и 0 если расписание уже тянули |
| карточка | ~5 на бумагу + 1 метаданные колонок на сессию |
| сектор | 21 на сессию + 1 на ISIN |
| делистингованный или погашенный выпуск | +2 на поиск по всей базе |

Портфель из 50 бумаг — около 100 запросов. Архитектура рассчитана на десятки бумаг;
для расчёта по всему рынку дешевле тянуть справочник и историю пачкой на дату.

Сбросить кеш внутри живой сессии (например, после биржевого обновления):

```python
import moex_bonds as mb
mb._CACHE.update(market=None, bondization={}, static={}, columns={},
                 sectors=None, emitters={})
```

## Рецепты

**Только посчитанное, без ошибок:**
```python
df = get_bond_yields(portfolio, date='2026-09-04', details=True)
ok = df[df.STATUS.eq('ok') & df.YTM.notna()]
```

**Отделить надёжные доходности от оценочных** (флоатеры и бумаги с офертой дают
систематический плюс к биржевой цифре — у биржи купон спроецирован по форвардной кривой,
у нас перенесён):
```python
df[df.COUPONS == 'known all coupons']
```

**Своя ставка для необъявленных купонов:**
```python
get_bond_yields(floaters, date='2026-09-04', assumed_rate=14.0)
```

**Цена из своего источника** (например, из отчёта депозитария):
```python
get_bond_yields(['RU000A0ZZ5H3', 'RU000A1038V6'], date='2026-09-04',
                price={'RU000A0ZZ5H3': 98.7, 'RU000A1038V6': 101.2})
```

sch = get_coupon_schedule(portfolio)

future.groupby(future.date.dt.to_period('M')).total_amount.sum()

## Грабли

- **Флоатеры систематически дают +0.3…0.9 п.п.** к биржевой доходности. Это следствие
  конвенции (перенос последней ставки против форвардной кривой биржи), а не ошибка.
  В отчёт такие бумаги стоит класть с пометкой `COUPONS`.
- **`PRICE_DATE` может быть сильно раньше `DATE`.** У неликвида цена подтянется из отката
  на 20 дней или вообще из первых дней торгов — доходность тогда считается по старой цене.
  Всегда смотреть `PRICE_DATE` и `PRICE_FIELD` при `details=True`.
- **Аномально отрицательный `YTP` при непустом `PUTDATE`** — почти наверняка оферта,
  которую ISS поставил на дату сбора заявок внутри купонного периода: выкуп без НКД
  за несколько дней до купона даёт двузначный минус. Отличить такую дату от настоящей
  оферты нечем.
- **T+1 на праздничной неделе.** Для даты оценки «сегодня» будущих сессий в истории ещё нет,
  и T+1 определяется как ближайший будний день — перед праздниками это даст сдвиг на день.
- **Валютные выпуски считаются в валюте номинала.** Пересчёта в рубли по курсу ЦБ нет;
  `FACEUNIT` показывает валюту.
- **Структурные облигации** (≈479 выпусков): биржа по ним доходность не публикует, расписание
  в ISS условно. Функция число выдаст, содержательно оно ничего не значит.
- **Расписание и доходность расходятся по необъявленным купонам** — намеренно:
  `get_coupon_schedule` показывает `NaN`, `get_bond_yields` переносит ставку.

## Что править, чтобы изменить поведение

| нужно | где |
|---|---|
| другое поле цены по умолчанию | `PRICE_CHAINS` + дефолт `price` в `get_bond_yields` |
| другая глубина отката цены | `LOOKBACK` |
| база расчёта (ACT/360 и т.п.) | `YEAR` — используется и в НКД, и в восстановлении ставки, и в дисконтировании |
| расчёт от даты торгов, а не T+1 | `next_trading_day` (вернуть `date`) — расхождение с биржей вырастет |
| НКД при выкупе по оферте | `bond_cashflows`, строка с `kind='redemption'` |
| свой набор колонок результата | `COLUMNS`, `SCHEDULE_COLUMNS`, `SECTOR_COLUMNS` |
| новый отраслевой индекс MOEX | `SECTOR_INDICES` |
| сектор по типу выпуска | `TYPE_SECTORS` |
